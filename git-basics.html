Git Basics

Git is a version control system: it tracks changes to files over time so you can review history, undo mistakes, and collaborate without overwriting each other's work. GitHub is a website that hosts git repositories — git is the tool, GitHub is one place to store and share what it tracks.

Installing & configuring git

Check whether git is already installed:

git --version

If it's missing:

  • macOS: xcode-select --install, or brew install git if you use Homebrew.
  • Windows: install Git for Windows, which also gives you Git Bash.
  • Linux: sudo apt install git (Debian/Ubuntu) or your distro's package manager.

Then tell git who you are — this name and email get attached to every commit you make:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
Tip

Use the same email you use for your GitHub account, or GitHub won't link your commits to your profile.

The three areas

Every git repository has three places a change can live:

AreaWhat it is
Working directoryThe actual files on disk that you edit.
Staging area (index)A holding area for changes you've marked to go into the next commit, via git add.
Repository (.git history)Permanent snapshots created by git commit.

This is why you add before you commit: staging lets you commit only part of what you changed, deliberately.

A change moves right as you add and commit it — and you can send it back left with restore before it's committed.

Starting a repository

Two ways to get a project under git:

# Start tracking a new/existing folder
git init

# Copy down an existing repository (e.g. from GitHub Classroom)
git clone https://github.com/org/repo.git

clone is by far the more common one in this course — you'll almost always be cloning a repo your instructor or GitHub Classroom already created.

Core commands

# See what's changed since your last commit
git status

# Stage a specific file, or everything
git add path/to/file.py
git add .

# Commit staged changes with a message
git commit -m "Add binary search implementation"

# See history
git log
git log --oneline

# See exactly what changed, line by line
git diff            # unstaged changes
git diff --staged   # staged changes
Tip

Write commit messages in the imperative mood — "Add feature", not "Added feature" or "Adds feature". Keep the first line under ~50 characters and describe why, not just what, if it's not obvious.

.gitignore

Some files shouldn't be tracked: build artifacts, virtual environments, editor settings, compiled binaries. List patterns for them in a .gitignore file at the root of your repo:

# .gitignore
__pycache__/
*.pyc
node_modules/
.DS_Store
.env
venv/
Warning

.gitignore only stops untracked files from being added. If a file is already committed, adding it to .gitignore won't remove it from history — you need git rm --cached <file> first.

Undoing changes

Git gives you several ways to undo, depending on how far the change has gone:

SituationCommand
Discard unstaged edits to a filegit restore <file>
Unstage a file (keep the edits)git restore --staged <file>
Edit the message of your last commit (not yet pushed)git commit --amend
Undo a commit but keep the changes as editsgit reset --soft HEAD~1
Undo a commit and discard the changes entirelygit reset --hard HEAD~1
Undo a commit that's already been pushed/sharedgit revert <commit>
Warning

git reset --hard permanently discards uncommitted work with no undo. Prefer git revert for anything already pushed — it adds a new commit that cancels out the old one instead of rewriting history.

Working with remotes

A "remote" is a copy of the repository hosted elsewhere — usually on GitHub.

# See what remotes are configured
git remote -v

# Connect a local repo to a GitHub repo you created
git remote add origin https://github.com/you/repo.git

# Send your commits to GitHub
git push origin main

# Pull down commits others have pushed
git pull origin main

git pull is really git fetch (download new history) followed by git merge (combine it with yours) — see Branching & Merging for what happens when that merge isn't automatic.
